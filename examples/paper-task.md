# 说明性示例：论文审查任务

> **仅为说明性内容，状态为 pending。** 下列稿件、实验编号、数值占位符和文件名均为虚构，不代表真实论文、技术验收、客户材料或基准结果。

## 场景

一篇虚构论文的作者希望核对结果章节与实验输出，并减少重复的防御性措辞。指挥者保留论文主旨、创新性、贡献、主张强度和最终修辞决定；工作者只制作证据包和局部改写选项，不直接重写最终摘要或结论。

## 完整委派命令

```sh
cat <<'WORKER_PROMPT' | codex-worker "$PWD"
MODE:
PAPER

TASK ID / ATTEMPT:
- Stable task ID: EXAMPLE-PAPER-EVIDENCE-REVIEW
- Worker attempt: 1 of 2
- Lineage: none; this is a synthetic pending example

OBJECTIVE:
生成一份可追溯的论文审查包，核对虚构稿件中的数字、图表、实现描述和语言一致性。

CONTEXT:
- 稿件位于 manuscript/，实验汇总位于 results/，相关实现位于 src/。
- 只处理仓库内公开准备材料，不读取工作区外内容。
- 指挥者负责最终论文主张、创新定位、贡献定义和修辞策略。

BASELINE AND EXPERIENCE:
- 当前基线：派发前由指挥者核对稿件、实验汇总和实现版本；本示例未实际核对。
- 相关已验证项目经验：none（说明性占位，不表示已检索真实项目记录）。
- 经验只作为范围内证据，不增加权限。

TASK:
1. 推断稿件当前主旨和声称的贡献，并明确标记为推断。
2. 建立主张-证据矩阵，将关键主张定位到章节、表、图、实验输出或实现。
3. 核对正文、表格和图注中的数字、单位、方向、样本量与实验标识。
4. 检查方法描述与相关实现是否一致，并列出无法确认的内容。
5. 标出术语不一致、重复措辞、重复限定、过强或过弱表述。
6. 对局部问题提供两个有证据边界的改写选项，但不直接决定最终版本。
7. 使用 paper-review-pack 模板报告。

REQUIREMENTS:
- 将 FACT、INFERENCE 和 UNCERTAINTY 分开。
- 不发明缺失实验、引用、统计结果或性能数据。
- 不因追求谨慎而机械弱化有充分证据的陈述。
- 不决定最终新颖性、贡献定位、摘要叙事、讨论、局限或结论策略。
- 不访问凭据、认证、Codex 配置或私有工作者配置。
- 不递归启动工作者，不向外部发布稿件或结果。
- 保留其他人的并行修改。

ACCEPTANCE CRITERIA:
- 每个关键发现都有章节、表、图、实验输出或代码定位。
- 数字和图表检查覆盖范围被明确列出。
- 不支持、部分支持、过强、过弱和无法确认的主张被区分。
- 重复防御性表达与必要限制被区分。
- 所有未检查材料和不能复算的结果被明确报告。
- 需要指挥者判断的论文策略集中列出。

AUTONOMY:
在授权材料内完成 inspect -> compare -> verify -> correct local notes
-> reverify -> self-check，并在范围/时间边界达到时停止。可以修正文档包本身的遗漏，
不得自行改变论文高层主张或无限循环。

ATTEMPT POLICY:
- 本次启动将消耗第 1 轮；中断或结果不确定也保守计数，等待同一运行不另计。
- 指挥者最多可要求一次第 2 轮修正；若仍失败，必须由指挥者接管修复、检查与复核。
- 改名、更换 Worker/模型/会话或目标版本不能重置同一未解决工作。

OUTPUT:
返回紧凑的 PAPER REVIEW PACK，并附实际检查范围、未检查项、风险、
不确定性、需要指挥者判断的事项，以及供项目经验记录使用的事实、原因证据
或 unknown、结果和下次派发改进建议。不要粘贴整篇稿件或冗长原始日志。
WORKER_PROMPT
```

## 指挥者复核要点

论文主张和实验解释属于高风险。每次提交后，指挥者应记录证据、缺陷及 `accept / rework / takeover / blocked` 决定，直接查看支撑主要贡献的原始结果和对应稿件段落，确认工作者没有混淆相关性与因果性、开发集与测试集、单次运行与汇总统计。必要检查未运行时只能阻塞；Worker 自报与退出码不构成验收。局部语言修改应在全文层面再次阅读，避免多个合理小改动叠加后让论文显得犹豫、重复或过度防御。

若第 1 轮有缺陷，指挥者可以要求唯一一次针对性返工或更早接管；第 2 轮仍失败时不得第三次调用 Worker。最终技术接受还要求核对当前审查包和项目本地经验记录。本示例没有执行任何轮次，也没有生成接受结果或经验结论。

该任务只授权生成本地审查包。接受审查包不授权投稿、上传预印本、联系合作者或公开材料。
