# Jev 配对实验：完成充值后的补测

日期：2026-09-25。项目：agent-orchestration-workflow。固定材料来源 commit：0c249b2475fd72c3f50c98e3653309027b1a5271。

## 结论与当前采用决定

补测完成：无 Jev 的 Astra 与 Jev 辅助 Astra 均为 18/18，与固定标签完全一致。Jev 本身为16/18，辅助组 Astra 纠正了两处错误。这一全量复核结构没有观察到质量收益，却增加 API 费用21.62%。保持默认OFF，仅保留显式SHADOW/ASSIST能力；不全局启用、不让JeV自动验收、不污染Worker适配经验。

## 配对设计

沿用充值前冻结的 packet.json 和 gold.json（三类各6条，共18条）。6条代码支持陈述，12条人工植入的反事实或无证据声明；它们不是18个独立真实生产任务，也不代表12个项目缺陷。9组源码/文档摘录存在共用材料。

两组均使用 openai/gpt-6-astra、reasoning=low、max_tokens=1800、同一系统指令、同一原始证据和全部18条审核要求。API不接收gold。辅助组只额外接收已有Jev的标签、概率、置信度和版本；原始证据只传一次，没有重复拼接整个筛查输出。先执行基线，再执行辅助组，没有将基线答案传入后者，没有根据结果调整标签或重新抽样。

此前两次基线失败保留在 baseline.json / baseline-attempt2.json；第二次确认402余额不足，第一次没有保存错误正文。用户明确确认充值并要求继续后，Commander直接恢复评测推理：只发起一次基线与一次辅助请求，没有自动重试。这不是代码Worker第三轮返工，也没有重置任何Worker执行账本。

## 误判和复核

Jev resolved model为typesafe/jev-1.13-20260917。输入7,097、输出813tokens。它把C06（99.9%可用率无证据）与C12（生产节省40%无证据）判为contradicted，固定标签为insufficient，置信度分别0.49、0.92。两组Astra都判为insufficient，因此辅助提示没有提高本样本准确率，幸而也没有造成错误采信。

关键经济性原因：要求主模型完整复核时，新增Jev并没有替代任何必要判断，反而增加978个Astra输入tokens。未来是否能通过文档筛选减少大量无关上下文，是另一种需要独立验证的设计，不能用本次结果证明。

## 验收与边界

Commander检查所有预测与冻结标签，离线脚本analyze_comparison.py复算费用/质量/时间并核对两组packet哈希一致。原始返回在resumed-*.receipt.json，整理结果在resumed-*.json，汇总在comparison.json。gold由同一Commander预先构造，非独立盲标；示例偏简单、样本小、包含人工负例。18/18不等于实际生产100%正确。

实现阶段72项离线测试通过。此次仅调整评测脚本的数据拼接和收据保存，并更新实验材料，没有改运行模块或全局配置；没有额外收费请求。实验runner离线校验通过。完整实现过程与充值前失败状态留存在REPORT-before-topup.md。

验收决定：ACCEPT有边界的配对评测完成；不接受“Jev普遍更优/更省钱”的主张。结果仍标为probe，不加入真实Worker适配度学习。

## 经验反馈

保持默认OFF。在本类短证据、全量强模型复核任务中，新增语义判断层不应被默认视为优化。需要计算下游新增context和纠错成本，不仅看Jev单价。下一轮如开展长文档相关性过滤，应另立样本与召回验收标准，验证减少上下文能否抵消漏检风险；不自动扩大此次收费实验。

适用范围：当前问题模板、冻结中文代码说明材料、Jev版本及Astra low配置。模型版本、任务分布、提示结构或缓存计费变化后重新评估。人的权威、Commander验收、Worker两轮限制保持不变。
