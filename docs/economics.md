# 编排经济性

高性价比编排把不同性质的工作分配到合适层级：人类拥有目标、预算、约束、最终验收与调整或否决权；指挥者把高价值认知用于策略、关键决策和风险相称的复核；能力足够且成本较低的工作者承担大批量阅读、实现、改写和验证。工作者在明确范围和预算内自主完成有限的修正循环，并用压缩证据包交付结果，可减少指挥者重复读取全部原始材料的成本。

已有授权在被撤销或完成前持续有效。人工监督不意味着每一步都要批准；预计超预算、范围或外部影响扩大、触及保留决定或证据不足时才升级。指挥者负责技术验收，人类始终可以接受、拒绝或调整或否决结果。

## 分开衡量三件事

| 指标 | 回答的问题 | 常见误读 |
| --- | --- | --- |
| 指挥者配额 | 昂贵或受限的指挥者容量减少了多少？ | 配额百分比不等于同百分比的货币或令牌 |
| 货币成本 | 端到端实际支付了多少？ | 只报工作者费用，遗漏指挥者、重试、集成和审查 |
| 总令牌量 | 全流程处理了多少输入与输出？ | 委派可能降低指挥者用量，却增加总令牌量 |

实际评估应分别记录未缓存输入、缓存输入和输出的用量及价格口径，并计入工作者、指挥者、协调、适配器/集成、重试、返工和审查成本。总耗时与人工时间也要分别记录；人工时间有业务价值，但不应在没有明确折算规则时悄悄混入模型账单。不同模型若使用不同分词器，令牌数不能直接横向比较。

## 说明性算例

假设单一流程的基线成本是 **100 个标准化货币单位**。在保持**相同验收标准**的编排方案中，指挥者策略与复核为 20，工作者为 12，协调与返工为 8，总计为：

```text
20 + 12 + 8 = 40
(100 - 40) / 100 = 60%
```

因此这个假设场景的节省为 **60%**。这只是算术示例，不是基准测试、历史实测或任何模型的价格；人工时间应另行记录，且只有交付结果按同一标准被接受，比较才成立。

## 盈亏平衡与不划算情形

委派的简化盈亏平衡条件是：

```text
指挥者规划与审查成本 + 工作者成本 + 协调/集成成本 + 重试/返工成本
< 同一验收标准下的可比基线成本
```

各项必须互斥计账：若模型账单已包含重试、规划或审查用量，分类展示后不得再次加总；固定订阅费用与配额消耗分别记录，分摊金额须说明口径。

如果需要折算人工时间，应在两边使用同一明确口径；不能量化时保留为独立指标。还应比较质量是否被接受、完成时间和风险，而不是只看调用账单。

以下情况通常不经济：任务很小而委派开销更大；上下文难以压缩且必须由指挥者全文重读；工作者能力与工具不匹配导致多次返工；适配器维护或安全审查成本过高；基线不可比；输出质量未达到相同验收标准；或者任务包含不能委派的关键判断。此时直接执行或缩小委派范围更合适。

使用[成本与质量复核模板](../templates/cost-review.md)记录实际数据。模型、供应商或版本变化时，还应按[工作者契约](worker-contract.md)做同任务试运行，不能从一次样例推断普遍节省。

## 灵感来源与证据边界

本文的动机之一是 Artforartsake99 的 Reddit 帖子 [“Astra + 8 Deepseek 4.1 subagents. Insanely cheap tokens.”](https://www.reddit.com/r/vibecoding/comments/1wg5ogw/astra_8_deepseek_41_subagents_insanely_cheap/)（查阅于 2026-09-19）。作者以第一人称称，Astra extra-high 指挥模型使用了每周订阅配额的 10%，DeepSeek 子工作者花费为 0.94 美元。

这是一则经验叙述，没有受控的单模型基线，也没有经独立验证的等效质量。10% 配额不等于 10% 货币成本或 10% 令牌量，0.94 美元也只覆盖其报告的工作者费用。因此它可作为测量问题的启发，不能作为价格、模型性能或普遍节省的证据。
