# 全局采用与回滚

全局采用分为两部分：用户级 `AGENTS.md` 保存简短决策规则，稳定资源目录保存完整模板。无需更换现有 Worker、模型、供应商或认证配置。

## 采用的默认行为

- 人拥有目标、授权与最终决定权；指挥者在授权内自主推进。
- 已处于执行 Worker 角色时，直接执行，不再次委派。
- 指挥者角色跟随当前主会话，不硬编码模型或供应商；能力不足时披露并升级，不假装已经切换模型。
- 每个委派任务使用稳定 ID，总计最多两次 Worker 执行；第二次仍失败时指挥者接管。同一未解决工作不能靠改名、换模型/会话或改目标版本重置次数。
- 派发前记录验收条件、允许范围、基线、轮次和相关已验证经验；交接后由指挥者记录证据、缺陷及接受、返工、接管或阻塞决定。
- 恢复时核对当前基线，避免重做已完成部分或沿用失效证据。
- 每个委派任务（含失败和阻塞）保留项目本地经验；短问题、小修复继续直接处理，可复用一条简短项目日志，不自动写全局记忆。

## 安装方法

由用户或指挥者执行配置修改，执行 Worker 不负责修改全局配置。

1. 读取当前用户级 `AGENTS.md`，确认是否存在覆盖文件或项目级指令冲突。
2. 备份原文件，保存摘要与差异；如果已有模板资源目录，也先备份。
3. 将本仓库的文档、模板、示例、scripts、tests、records 及引用资源复制到稳定目录，例如 `~/.codex/workflows/agent-orchestration-workflow/`，记录文件哈希。
4. 将上述默认行为合并进用户级指令。保留原有 Worker 命令、任务模式、安全禁止项和合理的直接处理规则；格式可替换，复核、两轮上限和经验职责不可删除。
5. 全局指令引用稳定资源目录，不能引用某个临时项目中的相对 `docs/` 路径。只在任务需要时读取模板，不在每次对话加载全部材料。
6. 核对写入内容、引用路径、快照哈希与差异。模型、网络、凭据和运行时参数不属于此次策略调整。

用户级指令能否被某个已有会话及时重载，取决于宿主行为。文件更新和静态核对不能证明所有旧会话已经采用；后续任务应核对实际加载的指令。无需为完成这次文件修改主动终止已有任务。

## 回滚

回滚前先检查全局文件是否有安装后的新改动。如果没有，用备份恢复原 `AGENTS.md`；如果有，先合并保留新改动，再移除本次增加的规则。资源目录独立保存，可恢复其旧备份；不要在仍有指令引用时直接删除。

## 验证边界

JSON 可解析、引用一致、备份可恢复和文件哈希匹配属于静态验收。实际成本、完成质量、模型是否遵守角色边界，以及跨会话恢复是否可靠，需要真实任务证据；本仓库不把静态验收称为优越性实测，也不提供自动调度、强制执行或运行时模型切换。
